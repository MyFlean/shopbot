# Feature Migration Matrix

Every capability, its business purpose, current implementation, and V2 status — evidence-based,
from direct code reads this session (see `SEARCH_V2_ARCHITECTURE_STUDY.md` and
`SEARCH_V2_MIGRATION_ARCHITECTURE.md` for citations).

| Caching (static config) | `@lru_cache` on banners/categories JSON files | shopbot-main: `home_page.py` | **Engine-agnostic already** | No migration needed | None | None | None |

**Overall picture:** the retrieval/ranking/routing core of Search V2 is complete and correct for
the one endpoint that uses it. The migration work is almost entirely about **building
gateway-level methods for capabilities V1's fetcher currently owns exclusively** (best-selling,
curated, flean-picks, category browsing, suggestions, PDP, alternatives/recommended), most of
which don't require new indexing work — the 3-field allowlist gap
(`review_stats`/`cons_list`/structured `ingredients`) and the `category_paths.keyword` query-fix
are the only two indexing/query-level blockers found.
